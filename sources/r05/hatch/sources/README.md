# R05 孵蛋 UI 候选源码

仅评审，不是游戏实录、游戏接入资源或新玩法。四种1600×900布局共用同一sample.json人工样例；母鱼与父羊均Lv.0，技能阶级人工设为+3/+3，用于展示只有母亲最高技能并列时才出现的玩家二选一。

## 重建

Python3 + Pillow（检查）+ CairoSVG，系统字体Noto Sans CJK SC。保留`build_hatch.py`与`assets/`相对位置：

```sh
python3 build_hatch.py --root /tmp/r05-hatch-rebuild
```

每方案生成main/parents/father_details/execute/result/success/empty_rules的SVG、HTML、PNG及review.json；输出只写指定目录。HTML、SVG已嵌入画像；assets来自当前项目`assets/r04/characters/{bubble_fish,electric_sheep}/idle.png`，保留原透明PNG，不从截图或视频提取。UI及像素蛋图形由本源码原创绘制。SVG/HTML用于编辑和静态评审，按钮本身不调用游戏。

## 页面与跳转建议

四版均保留竞技场/主线/仓库/孵蛋导航。切换应遵循当前代码：离开竞技场暂停并静音，回去不自动继续。选择亲本先按性别分组；详情里的精灵Lv与技能+n使用不同标签。

- A：亲本→继承→确认→结果，摘要保留另一亲本信息。
- B：父母两列与中央继承工作台同屏，底部执行。
- C：中央蛋与双亲关联图，下方选择继承技能。连线仅解释来源，不是新关系/谱系系统。
- D：母亲档案卡为主，父亲附卡、右侧继承清单与确认票据。卡堆仅视觉层次，不是新增收藏玩法。

共28张1600×900效果图及A的一张844×390独立手机横屏稿。empty_rules副图显示缺亲本无孵化操作与临时规则；主图是并列技能选择状态；parents副图是选母亲与详情状态，father_details独立副图显示父亲完整详情与共享样例；execute是即时孵化前确认，无等待时间/培养过程；result是成功和失败两种去向同屏说明，非同时发生。成功才入本机仓库；失败返回预览，若重新执行将重新随机，不承诺保存原失败结果。

A的phone图不是大图缩小：四个全局导航、两项继承选择和底部主操作均44像素高，文字最小14像素；父母详情/规则/确认/结果通过对应副状态查看。不证明真机触控可用。

## 已核对与未定

当前代码基线3dd29e8。子代种族和特性跟母亲、精灵等级固定0、后天全0；先天六项各自在父母对应范围随机。基础和最终没有定稿，均显示待定。技能1身份来自母亲最高阶技能，并列才玩家选择；其阶级与技能2执行时随机。技能2在母种族剩余4槽抽取，其中3个槽尚未设计，不虚构效果。

临时算法说明：本样例技能1阶级99%+3/1%+4；技能2阶级+1..+9权重9..1。这些来自当前临时代码，不是用户已批准的长期概率，故不作为主界面既定承诺。完整事实见上级目录FACTS.md与sample.json。

本轮未执行Godot、真实孵化写盘、触屏/真机或游戏回归；无游戏代码与保护配置改动。静态源码重建与图尺寸/路径检查分别记录在validation.json。
